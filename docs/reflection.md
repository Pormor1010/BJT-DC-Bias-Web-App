## คำถามที่ต้องตอบ

1. **ทำไมการเปิด `templates/index.html` ตรง ๆ (file://) จึงไม่เท่ากับการรัน Flask?**

   เพราะ `index.html` เป็น *template* ไม่ใช่หน้าเว็บสำเร็จรูป ข้างในมีที่ว่างของ Jinja เช่น
   `{{ form.vcc }}`, `{{ result.vce }}`, `{% if error %}` ที่ยังไม่ได้ถูกแทนค่า
   การเปิดด้วย `file://` จึงเห็นแต่ช่องว่างหรือโค้ด `{{ }}` ดิบ ๆ และเมื่อกดปุ่ม
   เบราว์เซอร์จะพยายาม POST ไปที่ `file:///.../calculate` ซึ่งไม่มีอะไรรับ
   (ขึ้น ERR_FILE_NOT_FOUND) ที่สำคัญคือไม่มี Python รันอยู่เลย จึงไม่มีใครคำนวณ
   ค่า VB/VE/VC/VCE ให้ และ path `/static/style.css` ก็ชี้ผิดที่ สีและหน้าตาจึงหายไป
   การรัน Flask ทำให้มีเซิร์ฟเวอร์คอยรับ request, เรียก `solve()` แล้วส่ง HTML
   ที่แทนค่าครบแล้วกลับมา — เท่ากับว่า "หน้าเว็บ" เกิดจาก Python ทุกครั้งที่เรียก

2. **ฟอร์มส่งข้อมูลไปถึง Python ได้อย่างไร?**

   เส้นทางเต็มคือ

   1. `<form method="post" action="/calculate">` ในเบราว์เซอร์ → ผู้ใช้กด
      "คำนวณ DC Bias"
   2. เบราว์เซอร์ห่อค่าทั้ง 7 ช่องเป็น **HTTP POST** แบบ
      `application/x-www-form-urlencoded` ส่งไปที่ `http://127.0.0.1:5000/calculate`
   3. Flask dev server รับ request แล้วจับคู่กับ route `@app.post("/calculate")`
      ใน `app.py` → เรียกฟังก์ชัน `calculate()`
   4. `calculate()` อ่านค่าจาก `request.form` ผ่าน `_parse()` ซึ่ง trim ช่องว่าง,
      แปลงเป็น `float` และคูณ 1000 เฉพาะช่องตัวต้านทาน (kΩ → Ω)
   5. ส่งค่าที่เป็น SI ทั้งหมดเข้า `solve(**params)` ใน `dc_bias.py` → ได้ dict
      ผลลัพธ์เป็น V, A
   6. `_display()` แปลงหน่วยสำหรับแสดงผล (A → mA/µA) และเติมข้อความ region
      ภาษาไทย
   7. `render_template("index.html", result=..., error=..., warnings=...)`
      ให้ Jinja แทนค่าลงตาราง แล้วส่ง HTML กลับไปเป็น response
   8. เบราว์เซอร์วาดหน้าใหม่ เห็นตัวเลขในตารางผลลัพธ์

3. **ถ้าแก้สมการใน `dc_bias.py` ต้องแก้ `index.html` ด้วยหรือไม่ เพราะอะไร?**

   ไม่ต้อง — และไม่ควรแก้ `index.html` เลย ถ้าแก้เฉพาะ *ตัวเลข* ที่ได้จากสมการ
   เพราะ template ไม่มีสมการและการคำนวณอยู่ในตัวมันเลย มันแค่รับ dict มาจาก
   `render_template` แล้วแสดง `{{ result.vce }}` เป็นต้น (กติกาใน `AGENTS.md`
   ห้ามใส่สมการหรือ hardcode ผลลัพธ์ใน template) การแก้สมการจึงจบที่
   `dc_bias.py` ที่เดียว และเทสต์ใน `tests/test_dc_bias.py` จะฟ้องทันทีถ้าค่าอ้างอิงเพี้ยน

   ข้อยกเว้นเดียวคือถ้าแก้จน *ชื่อคีย์หรือหน่วย* เปลี่ยน เช่นเพิ่ม `vcb` หรือเปลี่ยน
   `ic` จากแอมแปร์เป็นมิลลิแอมแปร์ในตัว `solve()` — กรณีนั้นต้องแก้ทั้ง `_display()`
   ใน `app.py` และแถวใน template ให้ตรงกัน ไม่งั้นจะได้ค่าว่างหรือหน่วยผิด

4. **ทำไมผลที่อยู่นอก Forward-Active จึงต้องมี warning? ยกตัวอย่างสถานการณ์ที่ตัวเลขดูปกติแต่ใช้งานไม่ได้**

   เพราะสมการที่ใช้ทั้งหมด ($I_B = (V_{TH}-V_{BE})/(R_{TH}+(\beta+1)R_E)$ ฯลฯ)
   ตั้งอยู่บนสมมติฐานว่า BJT อยู่ใน Forward-Active จริง (รอยต่อ Base–Emitter นำ,
   Collector–Base reverse bias) ถ้าค่าการคำนวณออกมาอยู่นอกช่วงนั้น ตัวเลขยัง
   ออกมาได้สวย ๆ แต่ไม่ตรงกับสิ่งที่วงจรจะทำจริง — โปรแกรมจึงต้องบอกผู้ใช้
   ไม่ใช่ปล่อยให้เชื่อตัวเลขนั้น

   ตัวอย่างที่ลองจริงในแล็บนี้: ตั้ง `RC = 47 kΩ` ค่า IC ยังขึ้นว่า 1.230 mA
   ดูปกติมาก แต่ VCE ที่คำนวณได้ติดลบ (−47.045 V) ซึ่งเป็นไปไม่ได้ทางกายภาพ
   แปลว่าจริง ๆ ทรานซิสเตอร์อิ่มตัว (VCE ≈ 0.2 V) ไม่ได้ขยายสัญญาณตามที่สมการบอก
   ถ้าเอาเลขนี้ไปออกแบบต่อจะเข้าใจผิดว่าได้สวิงไฟเต็มช่วง
   อีกกรณีคือ `R2 = 1 kΩ` ทำให้ VTH ≈ 0.119 V ต่ำกว่า VBE วงจรอยู่ใน Cutoff
   กระแสเป็นศูนย์ ไม่มี bias ให้ใช้งานเลย

5. **อะไรคือสิ่งที่เข้าใจผิดหรือยากที่สุดใน Lab นี้ และแก้อย่างไร**

   ตอนแรกผมเข้าใจว่าต้องให้หน้าเว็บ "เก่ง" คือคำนวณเองใน JavaScript จะได้ไม่ต้องพึ่ง
   เซิร์ฟเวอร์ แต่พออ่านโจทย์จริง ๆ แล้วโจทย์ต้องการให้ Flask เป็นคนคำนวณ
   และห้าม hardcode ผลลัพธ์ใน HTML — จึงต้องแยกให้ชัดว่าเบราว์เซอร์ทำหน้าที่แค่
   ส่งค่าและแสดงผล ส่วนสมการอยู่ใน Python

   สิ่งที่ยากที่สุดคือ **หน่วย** เพราะหน้าเว็บให้กรอก kΩ แต่สมการต้องใช้ Ω
   ถ้าลืมคูณ 1000 ค่าจะเพี้ยนไปพันเท่า (เช่นได้ IC หลักไมโครแอมป์แทนมิลลิแอมป์)
   วิธีแก้คือกำหนดกติกาเดียวว่า `dc_bias.py` รับ SI เท่านั้น และให้ `app.py`
   เป็นที่เดียวที่รู้จัก kΩ แล้วเขียนเทสต์ค่าอ้างอิง (VB 1.942 V, VE 1.242 V,
   VC 9.294 V, VCE 8.052 V) ไว้ดักไว้ — ถ้ามีใครเผลอแก้หน่วย เทสต์จะแดงทันที
   อีกเรื่องที่ต้องคิดหนักคือจะทำอย่างไรเมื่ออยู่นอก Active ซึ่งผมเลือกแนวทาง
   "แสดงค่าตามสมการ Forward-Active แล้วเตือน" ไม่ใช่คำนวณใหม่แบบ clamp VCE
   เพราะซับซ้อนเกินขอบเขตของ Lab นี้
