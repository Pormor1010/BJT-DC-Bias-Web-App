## คำถามที่ต้องตอบ

1. **เหตุใดการเปิด `templates/index.html` ตรง ๆ จึงไม่เท่ากับการรัน Flask?**

   เพราะ `index.html` เป็น *template* ของ Jinja2 ไม่ใช่หน้าเว็บสำเร็จรูป ข้างในยังมีตัวแปรเช่น `{{ form.vcc }}`, `{{ result.vce }}`, `{% if error %}` ที่ยังไม่ถูกแทนค่า การเปิดผ่าน `file://` เบราว์เซอร์จะอ่านไฟล์อย่างเดียว ไม่มี Python รันอยู่ จึงไม่มีใครคำนวณค่า DC Bias และเมื่อกดปุ่มเบราว์เซอร์ก็พยายามส่งฟอร์มไปยัง `file:///.../calculate` ซึ่งไม่มีเซิร์ฟเวอร์รับ request (ขึ้นข้อผิดพลาด) ส่วน `/static/style.css` ก็ชี้ไม่ถูกที่ ทำให้สีและหน้าตาหายไป การรัน Flask จึงจำเป็น — Flask เป็นเซิร์ฟเวอร์ที่รับ HTTP request, เรียกฟังก์ชันคำนวณใน `dc_bias.py`, แล้วส่ง HTML ที่แทนค่าครบแล้วกลับไปให้เบราว์เซอร์

2. **ฟอร์มส่งข้อมูลไป Python อย่างไร?**

   เส้นทางคือ: ผู้ใช้กดปุ่มใน `<form method="post" action="/calculate">` → เบราว์เซอร์ห่อค่า 7 ช่องเป็น HTTP POST (`application/x-www-form-urlencoded`) ส่งไปที่ `http://127.0.0.1:5000/calculate` → Flask จับคู่กับ route `@app.post("/calculate")` ใน `app.py` → เรียก `calculate()` → `_parse()` อ่าน `request.form` แปลงเป็นตัวเลขและคูณ 1000 สำหรับช่องตัวต้านทาน (kΩ → Ω) → ส่งค่า SI ทั้งหมดเข้า `solve(**params)` ใน `dc_bias.py` → ผลลัพธ์ถูกแปลงหน่วยโดย `_display()` → `render_template("index.html", result=..., error=..., warnings=...)` แทนค่าลงใน HTML แล้วส่งกลับให้เบราว์เซอร์วาดหน้าใหม่

3. **แก้สมการใน `dc_bias.py` แล้วต้องแก้ HTML หรือไม่? เพราะอะไร?**

   ไม่ต้อง ถ้าแก้เฉพาะ *ตัวเลข* ที่ได้จากสมการ เพราะ `index.html` ไม่มีสมการฟิสิกส์และไม่มีการคำนวณอยู่ในตัวเลย มันทำหน้าที่แค่แสดงผลจาก dict ที่ Flask ส่งมา (แสดง `{{ result.vce }}` เป็นต้น) ตามกติกาห้าม hardcode ผลลัพธ์หรือใส่สมการใน template การแก้สมการจึงจบที่ `dc_bias.py` ไฟล์เดียว และเทสต์ใน `tests/test_dc_bias.py` จะตรวจค่าอ้างอิงให้อัตโนมัติ

   ข้อยกเว้นคือถ้าแก้จนชื่อคีย์หรือหน่วยเปลี่ยน (เช่นเพิ่ม `vcb` หรือเปลี่ยน `ic` จากแอมแปร์เป็นมิลลิแอมแปร์ใน `solve()`) ก็ต้องแก้ทั้ง `_display()` ใน `app.py` และแถวใน template ให้ตรงกัน ไม่งั้นจะได้ค่าว่างหรือหน่วยผิด

4. **ทำไมผลใน Region ที่แบบจำลองใช้ไม่ได้จึงต้องมี Warning?**

   เพราะสมการทั้งหมดตั้งอยู่บนสมมติฐานว่า BJT ทำงานใน Forward-Active จริง (รอยต่อ Base–Emitter นำ, Collector–Base reverse bias) ถ้าค่าการคำนวณออกมาอยู่นอกช่วงนั้น ตัวเลขยังออกมาได้สวย ๆ แต่อาจเป็นไปไม่ได้ทางกายภาพ เช่น ตั้ง `RC = 47 kΩ` ค่า IC ยังขึ้นว่า 1.230 mA ดูปกติ แต่ VCE ที่คำนวณได้ติดลบ (−47.045 V) ซึ่งเป็นไปไม่ได้ — จริง ๆ ทรานซิสเตอร์อิ่มตัว (VCE ≈ 0.2 V) ไม่ได้ขยายสัญญาณตามสมการ ถ้าเอาเลขนี้ไปออกแบบต่อจะเข้าใจผิดว่าวงจรทำงานได้เต็มช่วง อีกกรณีคือ `R2 = 1 kΩ` ทำให้ VTH ต่ำกว่า VBE วงจรอยู่ใน Cutoff กระแสเป็นศูนย์ ไม่มี bias ให้ใช้งาน โปรแกรมจึงต้องเตือนแทนที่จะปล่อยให้เชื่อตัวเลขนั้น

## คำถามปิด Lab

> ถ้าตัวเลขคำนวณมือถูก แต่เปลี่ยน RE แล้วผลบนหน้าเว็บไม่เปลี่ยน
> จะตรวจค่าที่ส่งจากฟอร์มและค่าที่เข้าไปในฟังก์ชันอย่างไร?

### หลักคิด: ไล่จากต้นน้ำไปปลายน้ำ ไม่เดา

ค่า RE ต้องเดินทางผ่าน 5 จุด ก่อนกลายเป็นตัวเลขบนหน้าจอ

```
ฟอร์ม (name="re") → HTTP POST (payload) → Flask request.form
→ _parse() แปลง kΩ→Ω → emitter_bias() ใช้ในสมการ → _display()/template แสดงผล
```

ถ้าผลไม่เปลี่ยน แปลว่ามีจุดใดจุดหนึ่งในสายนี้ "ตัดวงจร" อยู่ ผมจะไล่ตรวจทีละจุด
โดยเก็บหลักฐานจริงในแต่ละชั้น ไม่ใช่แก้โค้ดเดาสุ่ม

### ขั้นที่ 0 — เช็คโหมดก่อน (สาเหตุที่พบบ่อยที่สุด)

ใน Lab 03 วงจร **Fixed Bias ไม่ใช้ RE เลย** (Emitter ต่อลงกราวด์ตรง ๆ) ถ้าลืมสลับ
dropdown เป็น `Emitter Bias` แล้วแก้ RE ผลจะไม่เปลี่ยนทั้งที่โปรแกรมถูกต้องแล้ว
ฟอร์มที่ดีจึงต้อง **ไม่แสดงช่อง RE ในโหมด Fixed** และหัวตารางผลต้องบอก
"โหมด: ..." เสมอ — ตรวจสองอย่างนี้ก่อนอย่างอื่น

### ขั้นที่ 1 — ตรวจว่าฟอร์มส่งค่าออกไปจริง

1. ดู Elements ว่าช่อง RE เป็น `<input name="re">` ไม่ได้ถูก `disabled`
   (ช่องที่ disabled จะไม่ถูกส่งไปกับฟอร์ม)
2. เปลี่ยน RE จาก `1` เป็น `2` แล้วเปิด DevTools → **Network** → คลิกแถว
   `POST /calculate` → แท็บ **Payload / Form Data**
3. ต้องเห็น `re: 2` และ `mode: emitter` ใน payload

ถ้าไม่เห็น `re` → ปัญหาอยู่ที่ template (ลืม `name`, ผิดฟอร์ม, ช่องถูกซ่อน/disable)
**ไม่ใช่**ที่สมการ จึงยังไม่ควรแตะ `dc_bias.py`

### ขั้นที่ 2 — ตรวจว่า Flask รับค่าอะไร

ใส่ log ชั่วคราวใน `calculate()` (แล้วลบออกภายหลัง)

```python
app.logger.info("mode=%s form=%s", mode, request.form.to_dict())
```

เปิดดู log ของ Flask ต้องเห็น `'re': '2'` และ `'mode': 'emitter'`

- ถ้า payload มีค่าแล้ว แต่ log ไม่ขึ้นเลย → route หรือ `action="/calculate"` ผิด
- ถ้าไม่มี `mode` → hidden input หาย ทำให้ระบบตอบ error "ไม่รู้จักโหมด" (ไม่เดาเป็น Divider)

### ขั้นที่ 3 — ตรวจการแปลงหน่วย kΩ → Ω

เพิ่ม log ใน `_parse()` ก่อนคืนค่า

```python
app.logger.info("params=%s", values)
```

ค่าที่ต้องเห็นคือ `re = 2000.0` (Ω) ไม่ใช่ `2.0` หรือ `2000000.0`

| เห็นค่า | แปลว่า |
|---|---|
| `re = 2.0` | ลืมคูณ `KILO` (1000) |
| `re = 2000.0` | ถูกต้อง — ไปตรวจชั้นถัดไป |
| `re = 2_000_000.0` | คูณซ้ำสองที่ (ฟอร์มคูณแล้ว และ `_parse()` คูณอีก) |

### ขั้นที่ 4 — ตรวจค่าที่เข้าไปในฟังก์ชันและสมการ

ใส่ `breakpoint()` หรือ print ที่บรรทัดแรกของ `emitter_bias()` ใน `dc_bias.py`

```python
def emitter_bias(vcc, rb, rc, re, beta, vbe):
    print("emitter_bias", vcc, rb, rc, re, beta, vbe)  # ชั่วคราว
    ib = (vcc - vbe) / (rb + (beta + 1) * re)
```

ต้องได้ A3 → `re=1000.0, ib=1.0263e-5` และ A4 → `re=2000.0, ib=9.401e-6`

- ถ้า `re` เป็น 2000 แล้วแต่ `ib` เท่าเดิม → **สมการผิด** (เช่นใช้ `re` ไม่ครบ
  หรือเผลอใช้ `rb` แทน) จุดนี้คือจุดที่ต้องแก้
- ถ้า `_solve()` เรียก `solve()` (Divider) แทน `emitter_bias()`
  → ตัวเลือกโหมดใน `app.py` ผิด แม้ค่าที่ส่งเข้ามาจะถูก

ค่าอ้างอิงที่ใช้เทียบ (VCC 12 V, RC 2.2 kΩ, β 100, VBE 0.70 V)

| กรณี | IB | IC | VCE |
|---|---|---|---|
| A3 · RE = 1 kΩ | 10.263 µA | 1.026 mA | 8.705 V |
| A4 · RE = 2 kΩ | 9.401 µA | 0.940 mA | 8.033 V |

### ขั้นที่ 5 — ตรวจว่าเป็นผลรอบใหม่จริง ไม่ใช่ผลค้าง

- Refresh แล้วยิง POST ใหม่ ดูว่า response กลับมา 200 และเป็น HTML ก้อนใหม่
- หัวตารางต้องขึ้น "โหมด: Emitter Bias"
- **IB ต้องเปลี่ยนตาม RE ด้วย** (10.263 → 9.401 µA) ไม่ใช่แค่ IC
- ถ้า IB เปลี่ยนแต่ IC ไม่เปลี่ยน → ตรวจ `_display()` และแถว `{{ result.ic }}`
  ว่าได้ค่าจาก dict ใหม่ ไม่มีค่าคงที่/hardcode ค้างอยู่
